给 QQ 群做一个有「人设」的 AI Agent

群里的 AI 机器人都有一个通病：一口标准的客服腔。你问它「今晚吃什么」，它回「您好，关于晚餐的建议如下：一、……」。功能上是对的，体验上是灾难的。于是有了这个项目（代号 Eidolon）：做一个有固定人设、有长期记忆、并且懂得什么时候该闭嘴的群聊 Agent。

整体设计

一条消息进来之后的处理流程被拆成四步：

  1. 监听：接收集消息，带上发言人昵称和最近的上下文；
  2. 决策：先判断「要不要说话」——这是和普通机器人最大的区别；
  3. 生成：把人设、相关记忆和上下文拼进 Prompt，生成回复；
  4. 记忆：把值得记的信息（谁喜欢什么、发生过什么梗）写进存储。

人设：一份 YAML 说了算

人设不写在代码里，全部抽到配置文件，改性格不用改代码：

name: 阿凛
persona: |
  你是 QQ 群里的普通大学生「阿凛」，不是助手。
  说话简短、口语化，偶尔用表情包，不喜欢说教。
  被问到专业问题时可以认真回答，但不要每次都长篇大论。
speak_rules:
  min_interval: 180        # 两次发言至少间隔 3 分钟
  mention_trigger: true    # 被 @ 时必回
  hot_words: [考试, 项目, 吃什么]
memory:
  store: sqlite
  top_k: 5

「要不要说话」的决策逻辑其实很朴素：

def should_speak(msg, state):
    if msg.mentions_bot:                    # 被 @ 必回
        return True
    if now() - state.last_speak < 180:      # 冷却期，装没看见
        return False
    return any(w in msg.text for w in state.hot_words)

踩过的坑

  • 人设漂移：对话轮次一多，模型慢慢变回「您好」腔。现在的缓解办法是每轮都完整重申人设，并在 few-shot 里放两条「反例」回复；
  • 记忆检索：一开始想上向量库，后来发现群聊场景里关键词检索 + 时间衰减已经够用，先把复杂的留给需要的时候；
  • 回复太长：限制生成 token 数，再加一层后处理把长句拆短、砍掉列表式输出——群里没人想读三段小作文；
  • 刷屏被踢：真实的教训。冷却时间从 60 秒提到 180 秒之后，群友们对它的态度从「烦」变成了「偶尔还挺有意思」。

下一步

短期计划三件事：主动发起话题（比如考试周到了主动冒泡）、多群之间保持人格一致、把单条回复的 token 成本压下来。这个项目会拿去参加大创和挑战杯，后续进展会继续写在这里。

做产品的一部分是做约束：一个什么都回、永远在线的机器人，反而没有人味。
